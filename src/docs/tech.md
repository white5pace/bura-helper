## Состояние приложения

- Глобальное состояние — только через **React Context** (`src/contexts/`).
- **Не использовать** сторонние сторы: Redux, Zustand, Jotai, MobX, Recoil и аналоги.
- Локальное UI-состояние страницы — `useState` / `useReducer`.
- Состояние форм — **react-hook-form** (локально для формы, не глобальный стор).
- Персистентность — Context + `localStorage`, по образцу `ParticipantsContext`.

## UI и компоненты

- Все базовые элементы интерфейса — из **shadcn/ui** (`src/components/ui/`).
- Новые UI-примитивы **только** через CLI: `npx shadcn@latest add <component>` (пример: `npx shadcn@latest add switch`). Не копировать registry-исходник в файл вручную и не писать аналоги Button, Input, Checkbox, Switch с нуля. После установки допустимы только variants/sizes в уже скачанном файле.
- Кастомные компоненты проекта — в `src/shared/ui/`; страницы — в `src/pages/`.
- Импорты UI: `@/components/ui/...`, утилиты: `@/lib/utils`.
- Иконки — только из `lucide-react`.
- **Тёмная тема — приоритет 3.** Сначала эксперимент в Figma, затем токены Tailwind / shadcn. Светлая тема остаётся текущей.

## Данные и localStorage

- Серверного бэкенда нет; всё состояние приложения хранится в **localStorage**.
- Ключи хранения — константы в одном месте (контекст или модуль storage). Сейчас три ключа:
  - `players` — ростер игроков (долгоживущий)
  - `teams` — каталог пар/команд (долгоживущий)
  - `currentGame` — сессия партии (`selectedPlayerIds`, `teamMode`, `currentTeamIds`; позже trump/dealer/scores)
- Модуль сессии: `src/lib/currentGameStorage.ts` (`load` / `save` / `defaultCurrentGame`, очистка legacy-ключей).
- «Начать новую игру» (`resetGame`) пишет пустой `currentGame`, не трогая `players` и `teams`.
- Состав команды — множество из двух id: порядок выбора не важен, одна пара игроков — одна запись в `teams` (`normalizePair` / `samePair`). Имена в партии читаются по `currentTeamIds` из каталога, не дублируются в сессии.
- Upsert в `teams` и запись `currentTeamIds` — по «Продолжить» на выборе игроков (командный режим, 4 игрока).
- In-memory индекс по паре игроков **не делать сейчас**: каталог маленький, линейный `find` достаточен; индекс не персистить.
- Чтение при инициализации, запись при изменении данных (`useEffect` или централизованный слой).
- Позже: персист одного ключа через `useStorage` из [reactuse](https://github.com/siberiacancode/reactuse/blob/main/packages/core/src/hooks/useStorage/useStorage.ts), когда ключей станет больше (история игр, настройки). Координацию нескольких ключей (`deletePlayer`, `sanitizeCurrentGame`) хук не заменяет.
- При ошибке парсинга JSON — fallback на пустое значение, без падения приложения.
- Типы данных описывать в TypeScript-интерфейсах; не полагаться на «сырой» JSON без проверки.

### История игр и отображение имён (когда появится `gameHistory`)

Источник отображаемого имени — **живая ссылка** (`playerId` / `teamId` в каталоге). Переименовали игрока или команду — в истории тоже новое имя.

В записи истории **сразу** кладётся слепок: имена игроков и название команды на момент конца партии. Слепок нужен только если ссылка недоступна (игрок или команда удалены): тогда UI берёт имя из слепка и может показать подпись вроде «команда удалена» / «игрок удалён».

Идентичность для фильтров и статистики — id (и пара игроков у команды), не строка названия. Удаление игрока или команды **не** удаляет записи истории.

## Формы и валидация

- Формы — **react-hook-form** с резолвером **zod**.
- Схемы валидации — рядом со страницей или в отдельном файле схем; сообщения об ошибках — на **русском языке**.
- Ошибки полей — через компоненты shadcn (`Field`, `FieldError`).

---

## Маршрутизация

- Маршруты объявляются в `App.tsx` через `createBrowserRouter`.
- Общая обёртка страниц — `MainLayout`.
- Параметры маршрута (`:id?`) — для режимов создания и редактирования на одной странице.

## Код

- TypeScript strict; без `any`, если можно обойтись.
- ESLint — перед коммитом/PR прогонять `npm run lint`.
- Минимальный diff: не рефакторить и не менять несвязанный код в рамках задачи.
- Следовать уже принятому в репозитории стилю (именование, структура файлов, паттерны контекста).
