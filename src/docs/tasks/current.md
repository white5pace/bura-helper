# Task: Главный экран игры — карточки

> Активная задача для оркестратора. Skill: `team-orchestrator`.  
> Шаблон: `src/docs/task-packet.template.md`

---

**Type:** feature

**Описание:** сверстать главный экран игры двумя отдельными компонентами и собрать из них страницу `/game`. Логику экрана реализовывать можно и нужно. Её делает только Frontend Developer: сессия, кто какой карточкой рисуется, счёт, раздающий, козырь, кнопка «Завершить раунд» и подтверждение перед уходом с экрана. Design Implementer логику не пишет — ни контекст, ни правила, ни переходы, ни запись счёта. Он отдаёт компоненты, варианты и Layout Spec.

Design Implementer делает оба компонента за один заход, по порядку. Это не один визуальный блок: карточка игрока и карточка игры — разные компоненты. Карточка игрока абсолютно накладывается на карточку игры. Обводку карточки игры взять из кадра и не растворять её в карточке игрока.

**1. Карточка игрока.** На ней счёт, имя и признак раздающего. Отдельный вид — с названием команды. Два визуальных варианта заливки: красный и чёрный. Какой вариант когда включать, решает Frontend Developer: красный — командный режим и игрок красной команды (порядковые №2 и №4, индексы 1 и 3 в `selectedPlayerIds`); чёрный — не командный режим или игрок чёрной команды (№1 и №3, индексы 0 и 2). Название команды на карточке только в командном режиме. Размеры, жирность и кегль из кадра сохранить в стилях компонента: мобильная база `html` — 18px, px из Figma делить на 18; если на 18 не делится — arbitrary value. Иконка раздающего уже есть: `src/assets/dealer.svg`. Сверить её с кадром карточки. Если размер не подходит — поправить этот файл так, чтобы одна иконка подходила и карточке, и подписи «Раздает:» на `/game-start`. Второй файл не заводить. После правки блок «Раздает:» на `/game-start` не должен поехать.

**2. Карточка игры.** Поле, на котором лежат от 1 до 4 карточек игроков, по центру — козырь. Иконки мастей уже есть, новые не рисовать: `src/assets/suit-clubs.svg` (крести), `suit-spades.svg` (пики), `suit-hearts.svg` (черви), `suit-diamonds.svg` (буби). Слоты и поворот карточек напротив описать так, чтобы страницу можно было собрать без Figma. Если в кадре есть кнопка «Завершить раунд», положить её в компоновку как контрол. Действие кнопки пишет Frontend Developer, не верстальщик. Диалог подтверждения верстальщик не делает: примитив уже есть.

Layout Spec — `src/docs/layouts/game.md`. Он описательный: дерево, слоты 1–4, кто повёрнут, абсолютное наложение карточки игрока на карточку игры, обводка поля, пути файлов, props и варианты (`red` / `black`, имя команды только в командном режиме, флаг раздающего, счёт числом). Цвета, кегль и жирность живут в CSS компонентов, не таблицей в layout. Компоненты положить в `src/widgets/`, не в `src/components/ui/`: это не примитивы shadcn. В конце layout — куда что положено, чтобы Frontend Developer собирал страницу только по этому файлу.

Frontend Developer после layout собирает `src/pages/Game.tsx` (сейчас `return null`) и реализует логику экрана. Маршрут `/game` уже есть. Данные брать из сессии: порядок `selectedPlayerIds`, `teamMode`, имена команд, `dealerId`, `trump`, счёт. Он же выбирает красную или чёрную карточку, показывает имя команды только в командном режиме, ставит иконку раздающего нужному игроку, кладёт козырь в центр, раскладывает 1–4 игроков и переворачивает карточки напротив. Счёт на карточке — из сессии; если поля ещё нет, завести его и показывать текущее значение (до раундов это 0). Кнопка «Завершить раунд» сразу никуда не ведёт: открывает подтверждение на уже стоящем `@/components/ui/alert-dialog`. Новый диалог и `DeleteConfirmDialog` не использовать — у того действие «Удалить». Вопрос в диалоге: «Вы уверены, что хотите закончить данный раунд?». Отмена закрывает его и оставляет игрока на `/game`. Подтверждение переходит на заглушку `/round-end`, без экрана выбора проигравшего и штрафных. Полноценное «Завершение игры» в эту задачу не входит; для `/game-end` допустима такая же заглушка, без логики конца партии.

Углы в этом файле устарели: в `GameCard.tsx` слоты уже переставлены руками. Frontend Developer правит описание под код, классы слотов не откатывает.

Порядок за столом — справа налево, снизу вверх:
- `slot1` — правый нижний, `align="end"`
- `slot2` — левый нижний, `align="start"`
- `slot3` — левый верхний, обёртка `rotate-180`, `align="end"`
- `slot4` — правый верхний, обёртка `rotate-180`, `align="start"`

Кого класть решает `GameCard`, не страница. Игроки приходят списком в порядке выбора. Места справа налево, снизу вверх: первый, второй, третий, четвёртый. Единственное исключение — двое: второй сидит в левом верхнем углу, не в левом нижнем. Таблицы на каждый состав и цепочки `if` по числу игроков не писать. Страница не передаёт `slot1`…`slot4`.

`PlayerCard` и `GameCard` — обычные компоненты без эффектов, им не место в `src/widgets/`. Перенести в `src/shared/ui/`. Сессию и диалог оставить на странице.

Иконки лежат в `src/assets/icons/`. Из `index.ts` их отдают именованным экспортом `export { dealer, clubs, spades, hearts, diamonds }`, не объектом `icons` и не `as const`. Имена в этом модуле только английские. Подписи на экране и значения козыря в сессии остаются русскими.

В карточке игрока два прямоугольника из кадра компонентов закрывают обводку карточки игры. Высоты карточки фиксированные: с названием команды и без него прямоугольники разной высоты. У имени минимальная высота одновременно максимальная, длинный текст обрезается многоточием.

Многоточие у имени и команды в карточке игрока оставляем на `line-clamp`. Встроенный браузер верстальщика показывал странный баг обрезки, в основном браузере он не воспроизводится — не чинить и не считать дефектом.

**Out of scope:** полноценные экраны «Завершение раунда» и «Завершение игры» (выбор проигравшего, штрафные, конец партии) — только заглушки маршрутов; настройки партии; отдельный режим «друг напротив друга» и экран на одного игрока сверх раскладки 1–4; новые SVG мастей; вторая иконка раздающего; новый alert-dialog с нуля; смена состава команд и порядка на `/participants`. Логику главного экрана и диалог подтверждения верстальщику не отдавать.
